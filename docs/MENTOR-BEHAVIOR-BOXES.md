# جعبه‌ی رفتار منتور (Mentor Behaviour Boxes)

> یک راهنمای کوتاه برای مدیر محتوا: **چطور برای هر برند و هر محصول تعریف کنی منتور چطور حرف
> بزند و چه اطلاعاتی بدهد** — و پشت‌صحنه چه اتفاقی می‌افتد.
>
> مسیر در پنل ادمین: **`/admin/mentor`** (منوی «رفتار منتور»).
> همچنین از صفحه‌ی هر برند (`/admin/content/brands/:id`) دکمه‌ی «تعریف رفتار منتور» و روی هر
> محصول دکمه‌ی «رفتار منتور» به همین فرم می‌رسد.

---

## ۱. جعبه‌ی رفتار چیست؟

یک رکوردِ محتوایی به‌ازای **هر برند**، **هر محصول** و **یک پیش‌فرضِ کل سایت** که دو کار انجام
می‌دهد:

1. **دانش**: محتوای جعبه به دانشنامه‌ی منتور اضافه می‌شود — قابل جست‌وجو، قابل ارجاع، و مثل بقیه‌ی
   محتوای تأییدشده تحت گاردریل عدد/ادعاست.
2. **رفتار**: لحن، نقش، بایدها و نبایدها به «دستور سیستمِ» مدل تزریق می‌شود؛ یعنی منتور درباره‌ی
   آن برند/محصول دقیقاً همان‌طور رفتار می‌کند که نوشته‌ای.

| سطح | کلید ذخیره‌سازی | کی استفاده می‌شود؟ |
|---|---|---|
| پیش‌فرض سایت | `mentor_guides/global` | برای هر سؤالی که برند/محصولِ صاحب‌جعبه نداشته باشد (یا جعبه‌اش خاموش باشد) |
| برند | `mentor_guides/brand:<brandId>` | وقتی سؤال به آن برند مربوط باشد |
| محصول | `mentor_guides/product:<productId>` | وقتی سؤال به آن محصول مربوط باشد (از همه خاص‌تر است) |

اگر هر سه وجود داشته باشند، **همه با هم** وارد می‌شوند، به ترتیبِ محصول ← برند ← پیش‌فرض.
قاعده‌ی ایمنی (پزشکی/حقوقی/مالی، اطلاعات شخصی، تزریق پرامپت) همیشه بر جعبه مقدم است.

---

## ۲. منتور چطور تشخیص می‌دهد سؤال درباره‌ی کدام برند/محصول است؟

سه سیگنال، به ترتیبِ اهمیت (`services/mentor-guides.ts → selectGuides`):

1. **بسته‌ای که چت در آن باز شده** — برند و محصولِ همان بسته.
2. **محدوده‌ی منابع بازیابی‌شده** — اگر بهترین منابع پیدا‌شده متعلق به برند/محصولی باشند.
3. **نامِ دقیقِ برند یا محصول در متن سؤال** — مثلاً «کرم مرطوب کننده کامان برای کی خوبه؟».

سیگنال ۳ مهم‌ترینِ آن‌هاست: حتی اگر جست‌وجو چیز زیادی پیدا نکند، منتور جعبه‌ی آن محصول را
**همیشه** در اولِ زمینه می‌گذارد. این همان چیزی است که باعث می‌شود منتور «کاملاً مسلط» به
اطلاعات آن برند/محصول باشد.

---

## ۳. فیلدها (هر کدام دقیقاً چه اثری دارد)

| فیلد | اثر |
|---|---|
| **فعال/غیرفعال** | غیرفعال = جعبه از دانشنامه و از دستور رفتار حذف می‌شود؛ متنش پاک نمی‌شود. |
| **لحن گفتار** (صمیمی / رسمی و کارشناسی / مربی فروش / کوتاه و تیتروار) | لحنِ پاسخ درباره‌ی این مورد را عوض می‌کند. |
| **اولویت (۰ تا ۲)** | چقدر زود در زمینه‌ی مدل دیده شود (عدد بیشتر = جلوتر). |
| **عنوان دلخواه** | اگر خالی بماند نام برند/محصول استفاده می‌شود. |
| **نقش منتور در یک خط** | «مثل یک کارشناس مراقبت پوست کنار دست بازاریاب» — هویتِ نقش. |
| **آنچه منتور باید کامل بداند** | جایگاه، مخاطب، ترکیبات، نکته‌های اصلی. این متن از حفظِ منتور است. |
| **نکات کلیدی** | جمله‌های کوتاهی که منتور می‌تواند عیناً بگوید. |
| **مزیت‌های اصلی برای مشتری** | مهمات فروش. |
| **اعتراض‌های مشتری + پاسخ تأییدشده** | اگر بازاریاب بپرسد «مشتری گفت گرونه، چی بگم؟» منتور همین پاسخ را می‌دهد. |
| **پرسش‌های پرتکرار** | پاسخ‌های کوتاهِ تأییدشده. |
| **حتماً بگو** / **هرگز نگو** | باید و نبایدِ صریح (مثلاً «ادعای درمانی نکن»، «با رقیب مقایسه نکن»). |
| **کلمات کلیدی** | نام‌های مستعار و معادل لاتین؛ کمک می‌کند سؤال به این جعبه برسد. |
| **دسترسی به پاسخ آزمون‌ها** | «پیروی از تنظیم کلی» / «مجاز — پاسخ را بگوید» / «ممنوع — فقط راهنمایی کند». |

> **نکته:** بعد از هر ذخیره، ایندکس دانشنامه خودبه‌خود «کثیف» علامت می‌خورد و در اولین درخواستِ
> بعدی به‌صورت افزایشی بازسازی می‌شود. اگر می‌خواهی همان لحظه مطمئن شوی، از
> `/admin/reports` → یا `POST /v1/admin/knowledge/rebuild` (فوق‌ادمین) استفاده کن.

---

## ۴. دسترسی به آزمون‌ها و پاسخ‌ها

پیش‌فرضِ سیاست‌ها (`Policy.mentorQuizAnswerAccess = true`) این است که **منتور آزمون‌ها را هم
می‌داند**: صورت سؤال، چهار گزینه و کلید پاسخ در دانشنامه ایندکس می‌شوند و منتور می‌تواند
گزینه‌ی درست را بگوید و دلیلِ ردِ بقیه را توضیح دهد — چون کاربرد واقعی‌اش «آموزش دادن» است، نه
پروکتوریِ امتحان.

سه سطح کنترل داری:

| سطح | کجا | مقدار |
|---|---|---|
| کل سایت | `/admin/policies` → `mentorQuizAnswerAccess` | `true` (پیش‌فرض) / `false` |
| یک برند یا محصول | جعبه‌ی رفتار → «دسترسی منتور به پاسخ آزمون‌ها» | `inherit` / `allow` / `hide` |
| ایمنیِ کد | `services/mentor.ts → checkInput` | تزریقِ پرامپت، پزشکی/حقوقی/مالی و اطلاعات شخصی همیشه مسدودند |

اگر `mentorQuizAnswerAccess` را `false` کنی، کلید پاسخ از متن ایندکس حذف می‌شود (و چون
`sourceHash` به این فلگ وابسته است، ایندکس در بازسازیِ بعدی پاک‌سازی می‌شود).

---

## ۵. اشراف بر تمام محصولات

به‌صورت پیش‌فرض (`Policy.mentorCatalogScope = 'all'`) محدوده‌ی برند در بازیابی **بی‌اثر** است:
منتور درباره‌ی **هیچ برند و محصولی** محدود نیست، حتی آن‌هایی که به این بازاریاب منتسب نشده‌اند.
بسته‌ها و قسمت‌های آموزشی همچنان بر اساس انتساب فیلتر می‌شوند (آموزشِ منتسب‌نشده هنوز مربوط به
این بازاریاب نیست).

اگر روزی خواستی منتور فقط درباره‌ی برندهای خودِ بازاریاب جواب بدهد،
`/admin/policies` → `mentorCatalogScope = 'assigned'`.

## ۶. زیرِ پوست (برای توسعه‌دهنده)

| لایه | فایل |
|---|---|
| مدل داده + ولیدیشن + CRUD ممیزی‌شده | `functions/src/services/mentor-guides.ts` |
| نوع آیتمِ دانشنامه (`guide`) | `functions/src/services/knowledge.ts` |
| تشخیصِ موضوع و تزریق به پاکتِ زمینه | `functions/src/services/mentor-ai.ts` (`buildGrounding`) |
| متنِ دستور رفتار + قاعده‌ی آزمون | `functions/src/ai/prompts.ts` (`guideSection`, `quizRule`) |
| API ادمین | `functions/src/routes/admin.ts` → `/admin/mentor/guides/...` |
| UI ادمین | `apps/web/src/pages/admin/MentorGuidesPage.tsx` + `MentorGuideDialog.tsx` |

### API

```text
GET    /v1/admin/mentor/guides?kind=brand|product|global|all&q=&onlyDefined=true|false
GET    /v1/admin/mentor/guides/global
PUT    /v1/admin/mentor/guides/global
GET    /v1/admin/mentor/guides/brand/:id
PUT    /v1/admin/mentor/guides/brand/:id
DELETE /v1/admin/mentor/guides/brand/:id
GET    /v1/admin/mentor/guides/product/:id
PUT    /v1/admin/mentor/guides/product/:id
DELETE /v1/admin/mentor/guides/product/:id
```

همه‌ی تغییرات در `audit_logs` با `entity=mentor_guides` و عمل‌های
`mentor_guide.created` / `.updated` / `.deleted` ثبت می‌شوند.

### ذخیره‌سازی (Cloudflare D1)

**هیچ مایگریشن جدیدی لازم نیست.** `D1Store` یک جدولِ عمومیِ سند (`docs(col, id, grp, data,
updated_at)`) دارد و هر کلکسیونِ جدید فقط یک مقدارِ جدید برای `col` است — جعبه‌ها در
`col='mentor_guides'` می‌نشینند. همان قاعده برای Firestore هم برقرار است.

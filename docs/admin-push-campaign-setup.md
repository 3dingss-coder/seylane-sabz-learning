# راه‌اندازی و عملیات کمپین‌های Push

این راهنما برای قابلیت مدیریت کمپین‌های Push در Worker پروژه نوشته شده است. اجرای این قابلیت به سرویس موجود ذخیره‌سازی و ارسال FCM متکی است و به سرویس زمان‌بندی جداگانه‌ای نیاز ندارد.

## قابلیت‌های پیاده‌سازی‌شده در کد

- ذخیره کمپین‌ها در collection پایدار `push_campaigns` از طریق `DocStore` موجود.
- ساخت پیش‌نویس و زمان‌بندی ارسال با زمان UTC.
- ویرایش پیش‌نویس یا کمپین زمان‌بندی‌شده تا قبل از شروع ارسال.
- ارسال فوری با تأیید کاربر، لغو کمپین پیش‌نویس/زمان‌بندی‌شده و تاریخچه وضعیت‌ها.
- مخاطب‌گیری از کاربران فعال به تفکیک همه کاربران، نقش، تیم یا کاربر.
- ثبت شناسه کمپین روی اعلان‌های ساخته‌شده و نمایش شمارنده‌های Push با وضعیت‌های ثبت‌شده در سیستم.
- اجرای کمپین‌های سررسیدشده از Cron موجود؛ تغییر وضعیت تراکنشی از ارسال تکراری ناشی از رقابت درخواست دستی و Cron جلوگیری می‌کند.

## پیش‌نیازهای Cloudflare

1. Worker با نام `seylane-sabz-learning` باید به دیتابیس D1 با binding به نام `DB` متصل باشد؛ پیکربندی فعلی پروژه در `wrangler.toml` این binding را تعریف می‌کند.
2. Trigger پانزده‌دقیقه‌ای `*/15 * * * *` باید فعال باشد. همین trigger کار `flush-push` را اجرا می‌کند و حالا کمپین‌های زمان‌بندی‌شده را هم بررسی می‌کند.
3. ارسال Push واقعی به پیکربندی معتبر FCM و اعتبارنامه‌های سمت سرور موجود در محیط نیاز دارد. مقادیر Secret را در مستندات، Git یا فرانت‌اند قرار ندهید.
4. اپلیکیشن وب باید از طریق مسیر موجود Worker و با احراز هویت ادمین/سوپرادمین در دسترس باشد.

## استفاده در پنل

1. وارد پنل ادمین شوید و صفحه «اعلان‌ها» را باز کنید.
2. زبانه «کمپین‌های Push» را انتخاب کنید.
3. نام داخلی، عنوان، متن، تصویر عمومی HTTPS، مسیر داخلی مقصد و مخاطب را وارد کنید.
4. برای پیش‌نویس، زمان ارسال را خالی بگذارید؛ برای زمان‌بندی، تاریخ و ساعت آینده را انتخاب کنید.
5. کمپین را ذخیره کنید. پیش‌نویس را می‌توان ویرایش کرد یا با تأیید صریح ارسال کرد. کمپین زمان‌بندی‌شده نیز تا قبل از شروع قابل ویرایش یا لغو است.
6. در تاریخچه، وضعیت و شمارنده‌های ثبت‌شده برای اعلان‌های ایجادشده و وضعیت Push را بررسی کنید.

## محدودیت‌های مهم گزارش

- «اعلان ساخته‌شده» به معنی تعداد رکوردهای اعلان داخل برنامه است، نه تعداد تحویل قطعی به دستگاه.
- «Push موفق» تعداد ارسال‌های موفقی است که Provider موجود گزارش داده؛ Web Push/FCM رسید خوانده‌شدن اعلان را تضمین نمی‌کند.
- نمایش تصویر به سیستم‌عامل، مرورگر و شکل URL تصویر بستگی دارد.
- کمپین‌های زمان‌بندی‌شده با دقت حداکثر حدود یک بازه Cron اجرا می‌شوند (حدود ۱۵ دقیقه)؛ این سیستم ارسال ثانیه‌ای نیست.
- صدای سفارشی اعلان عمداً خارج از محدوده است.

## تست و انتشار

پس از push شدن تغییرات به شاخه PR، CI باید این مراحل را اجرا کند:

- `npm run format:check`
- `npm run lint`
- `npm run build`
- `npm run typecheck`
- `npm test`
- بررسی Bundle مربوط به Cloudflare Worker و Assets

قبل از Merge، نتیجه تمام بررسی‌ها و یک تست دستی در محیط Preview را تأیید کنید. این تغییرات به‌خودی‌خود به معنی انتشار Production نیستند.

## بازگشت (Rollback)

در صورت بروز مشکل، ابتدا ارسال کمپین جدید را متوقف کنید و کمپین‌های زمان‌بندی‌شده را از پنل لغو کنید. سپس PR را اصلاح یا revert کنید و وضعیت کمپین‌های در حال ارسال را از تاریخچه و لاگ‌های Worker بررسی کنید. رکوردهای `push_campaigns` را دستی حذف نکنید؛ تاریخچه برای عیب‌یابی و ممیزی مفید است.

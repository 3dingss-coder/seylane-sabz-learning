## 3. پین‌های جدید (۱۳ تست — ۲ فایل)

### `pages/admin/governance.test.tsx` (۱۰ تست)

**PoliciesPage — قرارداد A8:**
- پنج بخش واقعی «آزمون و تکمیل / امتیاز / یادآوری و اعلان / منتور هوشمند / تماس صوتی با منتور» + ۱۳ برچسب فیلد + هشدار حاکمیتی «تغییرات فقط روی تلاش‌ها و رویدادهای جدید اعمال می‌شود»
- ذخیره با PUT واقعی: parse «۴۸، ۲۴» (ارقام/کامای فارسی) به `[48, 24]`، نمایش ساعات نرمال‌شدهٔ سرور (`24, 48`)، هرگز `updatedAt/updatedBy` برنمی‌گردد، هینت «تغییری هنوز ذخیره نشده…»، توست «سیاست‌ها ذخیره شد.»
- خطای فیلد سرور (422 با `details:[{field,message}]`) زیر فیلد مربوطه + پیام سرور

**AuditPage — قرارداد A10:**
- اکتور «سیستم» به‌جای id خام، نام واقعی اکتور از لیست کاربران، کدهای LTR (`package.published`، `push_run/run-9`)، diff قبل/بعد در `<details>«جزئیات»`
- فیلتر «فیلتر عملیات یا موجودیت» روی action/entity/entityId + حالت خالی واقعی «موردی نیست»

**ArchivePage — آرشیو ≠ حذف:**
- زیرنویس هشدار «حذف از آرشیو، اطلاعات را برای همیشه از دیتابیس پاک می‌کند.» + توضیح لیست سیاه («این شماره‌ها نمی‌توانند وارد اپ شوند…») + شمارهٔ واقعی فارسی در ردیف
- بازگردانی فقط با تأیید: دیالوگ «بازگردانی …؟» + «بازگردانی و اجازه‌ی ورود» + متن «کاربر از لیست سیاه خارج می‌شود…» → POST واقعی `/admin/archive/users/:id/restore` → توست «از آرشیو خارج شد و دوباره می‌تواند از اپ استفاده کند.» — هیچ درخواستی قبل از تأیید نمی‌رود
- حذف دائمی فقط با دیالوگ «حذف … از آرشیو؟» + هشدار کامل «حساب، پیشرفت آموزشی، نتایج آزمون، امتیازها و همه‌ی داده‌ها… قابل بازگشت نیست.» + «حذف برای همیشه» → DELETE واقعی
- گزارش‌ها: بازگردانی مستقیم با POST `{userId, packageId}` واقعی → «به گزارش‌ها برگشت.»؛ حذف با دیالوگ «حذف گزارش‌ها از آرشیو؟» → POST purge → «برای همیشه از دیتابیس حذف شد.»
- حالت‌های خالی هر دو تب: «لیست سیاه خالی است» / «گزارشی در آرشیو نیست» (قاعدهٔ spec: «طراحی حالت‌های edge قبل از صیقل happy path»)

# انتشار خودکار و عیب‌یابی Netlify

1. در Netlify → Project configuration → Build & deploy → Continuous deployment، مخزن GitHub `omidfreelanc-pixel/seylane-sabz-learning` و شاخهٔ `main` را متصل کنید. Build command: `npm run build`؛ Publish directory: `apps/web/dist`؛ فایل `netlify.toml` همین تنظیمات و مسیر `/v1/*` را دارد. با هر push به `main` پس از build موفق، نسخهٔ جدید خودکار منتشر می‌شود. تغییرات شاخهٔ کاری تا زمان merge شدن روی `main` به سایت اصلی نمی‌رسند.
2. در Deploys وضعیت آخرین deploy و لاگ build را بررسی کنید؛ در مرورگر Network درخواست‌های `/v1/auth/refresh`، `/v1/me/sections/.../media` و `/v1/files/signed/...` را بررسی کنید. 401، 404 و 500 دلایل متفاوت دارند. برای PWA قدیمی، یک بار تب را ببندید و دوباره باز کنید یا service worker را از DevTools پاک کنید.
3. **مهم: دادهٔ فعلی Netlify با `DATA_BACKEND=memory` در `/tmp` نگهداری می‌شود.** این مسیر روی هر instance پایدار یا مشترک نیست و هنگام cold start/deploy/scale ممکن است بازنشانی شود. کاربر، refresh token و فایل آپلودی ناپدید می‌شوند؛ این می‌تواند علت خروج ناگهانی یا خرابی فایل باشد. برای استفادهٔ واقعی باید backend پایدار (مانند Firestore + Firebase Storage با تنظیمات سرویس‌اکانت سرور) راه‌اندازی شود. صرفاً نگهداری فایل در GitHub مشکل دیتابیس/آپلودهای داخل اپ را حل نمی‌کند. تا آن زمان نمی‌توان ماندگاری نشست و فایل را تضمین کرد.
4. در این checkout هیچ فایل mp3/mp4/m4a/webm/ogg یافت نشد. seed برای فایل‌های آموزشی ناموجود فایل نمونهٔ ساختگی ایجاد می‌کند (`functions/src/seed/seed.ts`) و Netlify هم برای seed همین کار را می‌کند؛ این‌ها صدای/ویدیوی واقعی محصول نیستند. فایل‌های واقعی و فهرست دقیق «محصول ← فایل» باید تأمین شوند و بعد از آپلود و انتشار، از داخل سایت و با حساب آزمایشی پخش شوند. در اپ، پخش ساختگیِ بدون صدا هنگام خطای فایل حذف شده است؛ خطا اکنون صریح نمایش داده می‌شود.
5. ورود صرفاً با شماره بدون اثبات مالکیت، به معنی دسترسی هر شخص به حساب دیگران (از جمله مدیر) است. برای حذف رمز باید OTP پیامکی با ارائه‌دهندهٔ معتبر، محدودسازی تلاش‌ها و ثبت هزینه/کلید سمت سرور پیاده‌سازی شود؛ حذف کردن فیلد رمز به‌تنهایی امن نیست.

## ورود آزمایشی MVP

در حالت پیش‌فرض این نسخهٔ Netlify (backend حافظه‌ای، `APP_ENV` غیر `prod` و `VITE_APP_ENV` غیر `prod`) ورود با شمارهٔ حساب موجود و بدون رمز انجام می‌شود. در صفحهٔ ورود فقط دو میان‌بر «ادمین» و «بازاریاب» دیده می‌شود. **هر کسی که شمارهٔ یک حساب، از جمله ادمین، را بداند می‌تواند وارد شود؛ برای دادهٔ واقعی یا انتشار عمومی استفاده نکنید.** endpoint آزمایشی روی Firebase Auth و `APP_ENV=prod` فعال نیست؛ در build فرانت‌اند با `VITE_APP_ENV=prod` ورود با رمز باقی می‌ماند. `APP_ENV` و `VITE_APP_ENV` را هماهنگ تنظیم کنید. ثبت‌نام مستقیم هنوز رمز می‌خواهد؛ برای ورود بدون رمز باید شماره قبلاً ثبت شده باشد. پیش از انتشار، این مسیر آزمایشی را حذف و OTP واقعی را جایگزین کنید.

# فاز ۰ — کالبدشکافی کامل دیزاین‌سیستم دولینگو

> **هدف این فایل:** هر چیزی که از دیزاین‌سیستم دولینگو قابل استخراج است، در یک جا — تا ریزترین نکته.
> این سند «الهام» نیست؛ **مواد خام مهندسی معکوس** است. فازهای بعدی هر تصمیم را از همین‌جا اشتقاق می‌کنند.
>
> منابع: `design.duolingo.com` (پورتال برند)، بلاگ رسمی دولینگو (Design)، وایت‌پیپر *The Duolingo Method* (۲۰۲۳)، IEEE Spectrum دربارهٔ Birdbrain، مستندات کمکی دولینگو، و اندازه‌گیری مستقیم کنتراست رنگ‌ها با اسکریپت `tools/contrast.py`.
> هر عدد کنتراست در این سند خروجی واقعی `docs/design-system/tools/CONTRAST-REPORT.txt` است.

## ۰.۱ تز برند — جمله‌ای که همه‌چیز از آن می‌آید

> **«یادگیری باید اول از همه سرگرم‌کننده باشد.»** (fun first)

دولینگو یک اپ آموزش زبان نیست؛ یک **بازی است که تصادفاً چیزی یاد می‌دهد**. کل سیستم بصری این گزاره را پیکسل‌به‌پیکسل اجرا می‌کند. سه پیامد مستقیم:

1. **رنگ، تزئین نیست — معناست.** سبز یعنی «برو / درست است / پیش رفتی». قرمز یعنی «نه». زرد/نارنجی یعنی «جایزه گرفتی».
2. **هیچ لحظه‌ای خنثی نیست.** حتی خطا، حتی خالی‌بودن لیست، حتی قطعی اینترنت — همه با شخصیت و شوخ‌طبعی بیان می‌شوند، نه با یک آیکن خاکستری.
3. **احساس، بخشی از مکانیک یادگیری است نه تزئین آن.** دولینگو صریحاً به *emotional design principle* ارجاع می‌دهد: «آدم‌ها وقتی حالت هیجانیِ مساعد (کنجکاوی، اعتمادبه‌نفس، اضطراب کم) داشته باشند بهتر یاد می‌گیرند» — و در همان پاراگراف تأکید می‌کند «بدون افزایش بار پردازش اطلاعات بی‌ربط».

**درس شمارهٔ ۱ برای ما:** انرژی بصری و آرامش شناختی در تضاد نیستند. انرژی در *لحظه‌های پاداش* خرج می‌شود؛ بقیهٔ صفحه خلوت می‌ماند. دولینگو در هر صفحه **یک** نقطهٔ فریاد دارد.

## ۰.۳ تایپوگرافی — دو فونت، دو شغل، هرگز با هم

| | **Feather Bold** | **DIN Next Rounded** |
|---|---|---|
| نوع | اختصاصی دولینگو (bespoke) | لایسنس‌شده (Monotype) |
| شغل | تیتر، لحظه‌های ضربه‌ای، دکمه | زیرتیتر و متن بدنه |
| حروف | **فقط lowercase** | sentence case |
| الهام | فرم‌های خودِ Duo؛ حتی حرف `g` یک فلیک دارد که شبیه ابروی جغد است | — |

**قواعد سخت:**
- Feather Bold و DIN Next Rounded **هرگز در یک جمله ترکیب نمی‌شوند**.
- وزن پیش‌فرض **800** است؛ 700 در این سیستم «ضعیف» به‌نظر می‌رسد.
- تیترها ۲۵–۴۰٪ بزرگ‌تر از عرف برندهای محصول‌اند. Display از ۴۸px شروع می‌شود.
- letter-spacing روی دکمه‌های uppercase حدود `0.02em` تا `0.8px`.
- همهٔ گوشه‌های حروف نرم‌اند؛ هیچ ترمینال تیزی مجاز نیست.

**تحلیل:** این یک سیستم **دوصدایی** است. یک صدای «شخصیت» (Feather) و یک صدای «اطلاع» (DIN). تفکیک شغل، مهم‌تر از خودِ فونت است.

## ۰.۴ زبان فرم (Shape Language) — سه شکل پایه

مستندات ایلوستریشن دولینگو صریحاً سه شکل پایه را معرفی می‌کند:

1. **مستطیل گِرد (rounded rectangle)** — تنه، کارت، بدنه
2. **دایره** — سر، چشم، سرشانه
3. **مثلث گِرد (rounded triangle)** — منقار، گوش، حرکات پویا

پیامدها:
- **هیچ زاویهٔ تیزی وجود ندارد.** تیزی = تهدید؛ گردی = امنیت روانی برای اشتباه‌کردن.
- **حاشیهٔ ضخیم ۲px به‌جای سایهٔ نرم.** دولینگو عمق را با *خط* می‌سازد نه با *blur*. این یک تصمیم بزرگ است: حاشیهٔ solid در رندر موبایل ارزان‌تر از `box-shadow` بلوردار است و در هر اندازه‌ای crisp می‌ماند.
- **شعاع:** 12px دکمه، 16px کارت، 9999px چیپ و نوار.

## ۰.۵ آناتومی دقیق دکمهٔ سه‌بعدی — «لبه» (the lip)

امضای بصری دولینگو همین است. اسپک مستخرج:

```css
.duo-btn {
  background: #58CC02;
  color: #fff;
  border: none;
  border-radius: 12px;
  padding: 14px 20px;          /* min-height ≈ 50px */
  font: 700 15px/1.2 'Feather Bold';
  letter-spacing: .8px;
  box-shadow: 0 4px 0 #58A700; /* «لبه» — solid، بدون blur */
}
.duo-btn:active {
  transform: translateY(4px);
  box-shadow: none;            /* دکمه واقعاً «فشرده» می‌شود */
}
.duo-btn:disabled {
  background: #E5E5E5;
  color: #AFAFAF;
  box-shadow: none;            /* لبه حذف می‌شود = قابل فشار نیست */
}
```

**چرا کار می‌کند؟** چون یک affordance فیزیکی است: کاربر *قبل از لمس* می‌فهمد این چیز فشار دادنی است. و **حذف لبه در حالت disabled** یک کانال ارتباطی غیرمتنی است — بدون رنگ و بدون متن، «غیرفعال» را می‌گوید.

واریانت‌ها: سبز `#58CC02`/لبه `#58A700` · آبی `#1CB0F6`/لبه `#1899D6` · قرمز `#FF4B4B`/لبه `#EA2B2B`.

## ۰.۶ سایر اجزای پایه (اسپک مستخرج)

**نوار پیشرفت** — ترک `#E5E5E5`، ارتفاع ۱۶px، radius 9999، پر `#58CC02` با یک نوار باریک سبز روشن در بالا (highlight) که حس «براق و بازی‌وار» می‌دهد. انیمیشن پرشدن ≈ 320ms ease-out.

**Bottom Tab** — پس‌زمینه سفید، حاشیهٔ بالای ۲px `#E5E5E5`، آیکن/برچسب فعال `#58CC02`، غیرفعال `#AFAFAF`، متن ۱۱px Bold.

**جدول حالت‌ها (States) — دقیقاً همان چیزی که دولینگو مستند کرده:**

| حالت | رفتار |
|---|---|
| Empty | تیتر دوستانه + یک خط تشویقی با Wolf + یک CTA سبز + ایلوستریشن Duo. **هرگز سرد نیست.** |
| Loading (اولین paint) | بلوک‌های اسکلتون `#F7F7F7` **در ابعاد نهایی** یا Duo متحرک مرکزی. کاشی‌های مسیر fade-in می‌شوند. |
| Loading (بررسی پاسخ) | فقط خود دکمهٔ CHECK اسپینر می‌گیرد؛ **کل صفحه بلاک نمی‌شود.** |
| پاسخ درست | نوار بازخورد پایین + کپی شاد («Nice!») + دکمهٔ سبز CONTINUE + ding + کانفتی کوچک |
| پاسخ غلط | نوار پایین + «Correct solution: …» به‌صورت ساده و بدون سرزنش + دکمهٔ قرمز + کاهش قلب |
| خطای فیلد | حاشیهٔ ۲px قرمز، پس‌زمینه `#FFF0F0`، یک جملهٔ قابل‌اقدام |
| Disabled | بدون لبه، غیرقابل فشار؛ **به‌محض انتخاب گزینه دوباره فعال می‌شود** |
| پایان درس | **جشن تمام‌صفحه**: کانفتی + واکنش Duo + شمارش XP با انیمیشن + افزایش streak + یک CONTINUE سبز. «اوج هیجانی» |
| مایل‌ستون streak | مدال با ایلوستریشن شعله + عدد بزرگ + لهجهٔ Fox + share/continue |
| اتمام قلب‌ها | مدال توضیحی با سه گزینه (صبر / تمرین برای پرکردن / ارتقا). **لحن سبک، نه تنبیهی.** |
| اسکلتون | بلوک `#F7F7F7` در ابعاد دقیق نهایی، shimmer ملایم، گوشه‌ها همان radius کامپوننت |

## ۰.۷ سیستم کاراکتر — مهم‌ترین درس برای ما

### ۰.۷.۱ ترکیب بازیگران (cast)
Duo (جغد سبز) + Lily, Zari, Bea, Lin, Lucy, Eddy, Oscar, Vikram, Junior, Falstaff (روباه). ترکیب عمدی از **انسان و حیوان**، با تنوع سنی، قومیتی و شخصیتی.

### ۰.۷.۲ قواعد طراحی کاراکتر (از مصاحبهٔ رسمی Emily Chiu، تولیدکنندهٔ خلاق دولینگو)

1. **نام‌گذاری یکپارچهٔ بین‌زبانی.** نام باید در همهٔ زبان‌ها تقریباً یکسان بماند تا هویت کاراکتر نشکند. قبل از انتخاب، بررسی می‌کنند که نام در هیچ زبانی معنای بدی ندهد و تلفظش برای همه آسان باشد.
   > نکتهٔ ظریف: `Lin` و `Lucy` هر دو با «L» شروع می‌شوند — **عمداً**، تا بگویند این دو به هم مرتبط‌اند (مادربزرگ/نوه).
2. **تضادها جذب می‌کنند (opposites attract).** Zari برون‌گرا ↔ Lily درون‌گرا. Lin ریلکس ↔ Bea وسواسی. بیشتر دینامیک‌های داستانی از همین تضاد زاده می‌شوند.
3. **کاراکترِ هدف‌دار، نوشتنش آسان است.** «Béa اهداف خودش را دارد و جاه‌طلب است؛ هر کاراکتری که هدف داشته باشد راحت کاوش می‌شود، چون مدام درگیر چالش است.»
4. **اصالت از زندگی واقعی می‌آید، نه از کلیشه.** «هرچه دربارهٔ صفاتی که ما را ما کرده‌اند دقیق‌تر باشیم، بازنمایی واقعی‌تر و معنادارتر می‌شود.»
5. **تنوع برای همذات‌پنداری است:** «مهم بود قومیت، شخصیت و سن متنوع باشد تا یادگیرنده‌های سراسر جهان بتوانند با **حداقل یکی** از کاراکترها ارتباط بگیرند.»
6. **کاراکترها در تمرین‌ها «حرف می‌زنند»** — جمله‌ای که کاربر ترجمه می‌کند از دهان کاراکتر بیرون می‌آید. کاراکتر یک تزئین نیست، **رسانهٔ محتواست**.

### ۰.۷.۳ پیکربندی و انیمیشن (Rive)
دولینگو از **Rive** استفاده می‌کند، نه ویدیوی prerender:
- فایل `.riv` سبک؛ state machine منطقی به‌جای تایم‌لاین دستی
- ورودی‌های state machine: `isSpeaking`, `mouthShape`, `isCorrect`, `isWrong`, `isThinking`
- **Viseme:** شکل دهان متناظر با آوای گفتار. دولینگو **۱۵–۲۰ شکل دهان** و **۲۰+ حرکت دهان** دارد. حداقل کاربردی برای بقیه ≈ ۱۰ (A, E, O, M بسته, F/V, L, CH/J, Neutral, Smile, Surprise).
- ساختار استخوان: سلسله‌مراتب bone برای بدن و سر، کنترل کج‌شدن سر، تنفس، پلک، ردیابی مردمک، ابرو برای احساس، سوئیچ شکل دهان، حرکت ثانویهٔ دست/بال.
- لایه‌بندی artboard: هر کاراکتر از artboardهای تودرتو ساخته و در یک artboard «Character» ادغام می‌شود تا انیمیشن حرف‌زدن مستقل از انیمیشن بدن اجرا شود → **حجم فایل کوچک می‌ماند**.
- زنجیرهٔ lip-sync: متن → TTS سفارشی برای هر کاراکتر → مدل تشخیص گفتار/تلفظ داخلی → زمان‌بندی هر کلمه و فونم → نگاشت به viseme.

**چرا این مهم است؟** چون دولینگو ۴۰+ زبان دارد و امکان ندارد lip-sync را دستی انیمیت کند. **سیستم، به‌جای asset، تولید می‌کند.**

### ۰.۷.۴ کاراکتر در خدمت محصول، نه برند
- Duo در Empty state، جشن، یادآوری، خطا و ویجت حاضر است.
- **ویجت**: چهرهٔ Duo هرچه روز جلو می‌رود و درسی انجام نشده، **نگرانش‌تر** می‌شود — یک مکانیزم «عذاب وجدان» ملایم و دیدنی.
- کاراکترها لباس/اسکین می‌گیرند → **فروش کالا** (Gems) و **بیان هویت** همزمان.

## ۰.۸ اقتصاد گیمیفیکیشن — فهرست کامل با اعداد

### ۰.۸.۱ Streak (زنجیرهٔ روزانه) — قوی‌ترین اهرم
- شمارش روزهای متوالی با حداقل یک درس. آیکن: **شعله**. سرِ نیمه‌شب ریست می‌شود.
- هر هفته که کامل شود، یک نوار نارنجی-قرمز در تقویم streak.
- **Streak Freeze**: از قبل خریدنی (۲۰۰ Gems)؛ تا ۲ عدد همزمان قابل equip (۵ عدد در سطح ۱۰۰ روز). یک روز را «منجمد» می‌کند: streak نه زیاد می‌شود نه می‌سوزد.
- **Streak Repair**: اگر Freeze نداشتید، تا ۳ روز فرصت دارید با Gems زنجیره را برگردانید.
- **Weekend Amulet**: محافظت دو روزه برای آخر هفته.
- **Streak Society**: در روز ۷ → عضویت + تریال Super؛ روز ۳۰ → آیکن اختصاصی اپ؛ روز ۱۰۰ → اسلات اضافهٔ Freeze؛ روز ۳۶۵ → نشان VIP در لیدربورد. بعد از ۸۰۰، هر ۲۵ روز یک جشن.
- **Friend Streak** (از ژانویهٔ ۲۰۲۵): تا ۵ دوست؛ هر دو طرف باید درس بدهند؛ اگر یکی جا بماند می‌توان nudge فرستاد و طرف مقابل می‌تواند برای دیگری Freeze استفاده کند.
- **داده‌های اثر:** رسیدن به streak ۷ روزه → **۳٫۶ برابر** احتمال ادامهٔ دوره. Streak Freeze → **۲۱٪ کاهش churn** در کاربران در معرض ریزش. داشتن حداقل یک Friend Streak → **۲۲٪** افزایش احتمال انجام درس روزانه.

### ۰.۸.۲ Leagues (لیگ‌ها)
- ۱۰ سطح: Bronze, Silver, Gold, Sapphire, Ruby, Emerald, Amethyst, Pearl, Obsidian, Diamond.
- هر دوشنبه **۳۰ کاربر** به‌صورت تصادفی گروه می‌شوند؛ رقابت XP هفتگی.
- منطقهٔ صعود/سقوط: در Bronze ۲۰ نفر از ۳۰ صعود می‌کنند؛ از Sapphire به بالا فقط ۷ نفر؛ در Obsidian فقط ۵.
- **League Repair**: ۲۰۰۰ Gems برای فرار از سقوط.
- ریست هفتگی = هر دوشنبه یک شروع تازه → از ناامیدی بلندمدت جلوگیری می‌کند. اوج درگیری: یکشنبه و دوشنبه.

### ۰.۸.۳ دو-ارزی (Dual Currency)
- **XP** — ارز *جایگاه*؛ فقط جمع می‌شود، خرج نمی‌شود. سوخت لیگ‌ها.
- **Gems** (در وب: Lingots) — ارز *خرج‌کردنی*. قیمت‌ها: Streak Freeze ۲۰۰ · Heart Refill ۶۵۰ · League Repair ۲۰۰۰ · افکت‌های انیمیشنی ۵۰۰ · لباس Duo.
- معنا: هر خرید یک **تصمیم اقتصادی** است — لذت آنی در برابر گزینهٔ آینده.

### ۰.۸.۴ Daily Quests + صندوق‌ها
- هر روز ۳ مأموریت تازه (XP مشخص، درس بدون غلط، حفظ streak).
- پاداش: **صندوق** با کیفیت متغیر — Bronze (کم) / Silver (متوسط) / Gold (Gems + بوست ۱۵ دقیقه‌ای XP).
- **پاداش متغیر = همان مسیر دوپامینی ماشین اسلات.** اما هوشمندانه: کاربر *حدوداً* می‌داند چه چیزی ممکن است بگیرد، پس حاضر است برایش تلاش کند.

### ۰.۸.۵ Hearts → Energy
- قبلاً: ۵ قلب؛ هر پاسخ غلط = ۱ قلب؛ صفر = انتظار (هر ۵ ساعت یکی) یا تبلیغ یا پرداخت.
- اکنون: **Energy** — کاربران رایگان با ۲۵ واحد شروع می‌کنند؛ **هر تمرین یک واحد می‌گیرد، درست یا غلط**؛ با بوست‌های ردیفی ۱–۵ واحد برمی‌گردد.
- **نقد صادقانه (و برای ما مهم):** سیستم Energy حلقهٔ بازی را می‌شکند. با قلب، *مهارت* تعیین می‌کرد چقدر بازی کنی؛ با Energy مهارت تقریباً بی‌اثر است → **انگیزهٔ درست‌جواب‌دادن کم می‌شود.** این یک اشتباه طراحی است که ما نباید تکرار کنیم.

### ۰.۸.۶ موتور بازگشت (Retention Engine)
- **الگوریتم Bandit خوابیده-بازیاب (sleeping, recovering bandit)** برای زمان‌بندی نوتیفیکیشن: الگوریتم‌های bandit معمول فرض می‌کنند همهٔ گزینه‌ها همیشه در دسترس‌اند؛ ولی کاربری که نوتیفش را خاموش کرده یا اپ را پاک کرده، دیگر «بازی» نمی‌کند. دولینگو این را مدل می‌کند.
- **طراحی هویت** در متن نوتیفیکیشن: «You're a streak legend. Don't stop now.» · «People with streaks like yours never skip.» · «Future You will be proud you practiced today.»
  → پیام نیست، **هویت‌سازی** است. «انگیزه رفتار موقت می‌سازد؛ هویت رفتار دائم.»
- **نقد صادقانه:** حجم نوتیفیکیشن زیاد است (گزارش‌هایی از ۵ یادآوری پشت‌سرهم بعد از یک درس). مرز بین انگیزه و مزاحمت نازک است.

## ۰.۹ معماری اطلاعات و علم یادگیری

- **The Path**: از ۲۰۲۲ درخت مهارت (skill tree) جای خود را به **یک مسیر خطی** داد. واحد → درس → تمرین. کاربر دیگر «انتخاب نمی‌کند چه یاد بگیرد»؛ سیستم انتخاب می‌کند. این کاهش بار تصمیم، خودش یک مکانیک انگیزشی است.
- **Birdbrain**: رگرسیون لجستیک الهام‌گرفته از *Item Response Theory*؛ احتمال پاسخ درست را تابعی از «سختی تمرین» و «توانایی یادگیرنده» می‌گیرد. آپدیت با یک گام SGD بعد از هر تمرین — تعمیمی از **Elo** در شطرنج. نسخهٔ ۲ به‌جای یک عدد، یک **بردار چندبُعدی** از توانایی نگه می‌دارد تا ضعف‌های خاص را ببیند. تصمیم در ~۱۴ میلی‌ثانیه.
- **Goldilocks difficulty**: نه آنقدر سخت که کلافه شوی، نه آنقدر آسان که یاد نگیری.
- **Half-Life Regression (HLR)**: پیش‌بینی *کی* فراموش می‌کنی → زمان‌بندی مرور (spaced repetition).
- **دادهٔ رهاشده هم داده است**: نشست‌های نیمه‌تمام هم به مدل می‌روند؛ ترک درس یکی از روشن‌ترین سیگنال‌های «خیلی سخت بود» است.
- **تولید محتوا**: طراحان یادگیری هنوز مالک برنامهٔ درسی‌اند (اهداف گرامری، سطوح CEFR)؛ اما به‌جای نوشتن تک‌تک تمرین‌ها، **پرامپت‌های ساختاریافته** («زیر ۷۵ کاراکتر، سطح A2، زمان گذشته، بدون فعل بی‌قاعده») می‌نویسند و AI واریانت می‌سازد؛ Birdbrain کیفیت/سختی را می‌سنجد و انسان انتخاب نهایی می‌کند.
- **affordance-based design**: «یادگیرنده بداند کجا نگاه کند و چطور تعامل کند» — ترتیب تمرین و سختی، خودش راهنماست.
- **embodied cognition**: در اپ ریاضی، کاربر عقربهٔ ساعت را با انگشت می‌چرخاند. **یادگیری با انجام، نه با خواندن.**

## ۰.۱۰ رفرش تب‌های اصلی (فوریهٔ ۲۰۲۶) — تازه‌ترین درس سیستمی

دولینگو در فوریهٔ ۲۰۲۶ تب‌های اصلی را بازطراحی کرد. خلاصهٔ دقیق آنچه منتشر کردند:

**مشکل:** تب‌ها به‌مرور اضافه شده بودند؛ هرکدام به‌تنهایی خوب بود اما با هم «یک خانواده» نبودند — اندازهٔ هدرها فرق داشت، تایپوگرافی سلسله‌مراتب نداشت، فاصله‌گذاری نامنظم بود.

**روش:** یک اسپرینت واگرا با چهار جهت افراطی:
1. **Punchy** — هدرهای رنگی توپُر و پرکنتراست
2. **Soft** — گرادیان‌های آرام و رنگ‌های ملایم
3. **Modular** — چیدمان کارتی و انعطاف‌پذیر
4. **Flat** — مینیمال با فضای سفید زیاد

**دو تنش اصلی که کشف کردند (و برای ما طلاست):**
- **یکدستی باید با «هدف» متعادل شود.** «استفاده از آرورک در هدر همهٔ تب‌ها یکدست است، اما اگر فضای زیادی بگیرد و هیچ چیز مفیدی نگوید، زورکی است.»
- **سادگی باید با «وضوح» متعادل شود.** «طراحی خوب یعنی بدانی چه را حذف کنی و چه را نگه داری.»

**راه‌حل سیستمی:**
- **هدرهای سطح‌بندی‌شده (tiered headers)** بر اساس هدف هر تب، با **عنوان در موقعیت و اندازهٔ ثابت** در همهٔ تب‌ها.
- **سیستم تایپ با حداقل تعداد سبک** — یکدست و عمدی.
- **تمیزکردن فاصله‌گذاری:** به‌جای زورچپاندن container دور هر بخش، از **فضای سفید اطراف کامپوننت** استفاده کردند.

**فرایند کیفیت:** همکاری تنگ با مهندسی، **QA با اورلی‌های طراحی (design overlays)** برای self-QA، و dogfooding داخلی روی زبان‌ها و دستگاه‌های مختلف.

**نتیجه:** «درگیری در همهٔ تب‌ها بالا رفت در حالی که معیارهای اصلی یادگیری حفظ شد.»

## ۰.۱۳ خلاصهٔ اجرایی فاز ۰ — ۱۲ اصلی که به فازهای بعد می‌روند

1. **یک تز، یک رنگ معنایی، یک CTA در هر صفحه.**
2. **عمق با حاشیهٔ solid ساخته می‌شود، نه با blur.** (ارزان‌تر در موبایل، crisp در هر اندازه)
3. **دکمه یک جسم فیزیکی است:** لبهٔ ۴px، فشار با translateY، حذف لبه = غیرفعال.
4. **دو صدای تایپوگرافیک:** صدای شخصیت و صدای اطلاع، هرگز در یک جمله.
5. **سه شکل پایه، صفر زاویهٔ تیز.**
6. **کاراکتر رسانهٔ محتواست، نه ماسکوت تزئینی** — و باید هدف و تضاد داشته باشد.
7. **استخوان کاراکتر یک سیستم است** (state machine + viseme)، نه صدها فایل ویدیو.
8. **اقتصاد دو-ارزی:** ارز جایگاه (فقط جمع) + ارز خرج‌کردنی (تصمیم اقتصادی).
9. **بخشش، بخشی از مکانیک است نه استثنا** — Freeze/Repair از روز اول.
10. **هر لحظه یک حالت طراحی‌شده دارد:** Empty/Loading/Error/Disabled/Celebration.
11. **یکدستی ↔ هدف، سادگی ↔ وضوح** — دو توازنی که هر بازطراحی باید صریح درباره‌شان تصمیم بگیرد.
12. **اندازه‌گیری، بخشی از دیزاین است.** بدون رویداد و بدون A/B، گیمیفیکیشن حدس است.
